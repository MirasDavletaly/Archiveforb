# Company Files — общее файловое хранилище

Веб-приложение по ТЗ «Technical Specification for Shared File Storage»: папки отделов, доступ по группам, закрытые подпапки, которые начальник отдела настраивает сам, конфиденциальные папки, корзина, версии, внешние ссылки с паролем и сроком, журнал действий, бэкап.

Стек: Node.js 22.13+ (встроенный SQLite), без фреймворков. Зависимости: только два шрифта.

## Запуск на этом компьютере

```powershell
npm install        # один раз
npm run admin      # создаёт учётку admin и печатает временный пароль
npm start          # http://localhost:8800
```

При первом входе admin меняет временный пароль на свой.

Порт 8800 выбран потому, что 80, 443 и 8080 на этом ПК заняты. Поменять порт можно в `.env` (образец в `.env.example`).

Самопроверка: `npm run check` поднимает приложение на временной папке и проверяет 5 пунктов из раздела 10 ТЗ плюс правила безопасности.

## Первые шаги (IT)

1. **People** — создайте учётки сотрудников. Каждый получает временный пароль и личную папку на 20 ГБ.
2. **Folders and quotas** — создайте отделы (папка + архивная папка + группа, начальник получает Manage), проекты и конфиденциальные папки.
3. **Groups** — добавьте людей в группы отделов и в **Managers**.
4. Внутри своей папки начальник отдела сам создаёт подпапки и через **Manage access → Restrict this folder** закрывает их, без IT.

## Как устроены права

| Уровень | Что даёт |
|---|---|
| Read | смотреть и скачивать |
| Edit | создавать, менять, удалять |
| Manage | Edit + настраивать доступ к подпапкам |

- **По умолчанию всё закрыто.** Новый сотрудник видит только свою личную папку. Раздел, папку или отдельный файл открывает **Manager** (везде, кроме конфиденциальных и личных) или **IT** (разделы и папки, которые создаёт IT; файлов IT не видит). Делается это так: **Who has access → Edit → + Add person**, затем отметить одного или нескольких людей и выбрать Read или Edit. Доступ группы Managers меняет только IT, поэтому менеджеры не могут закрыть доступ сами себе.
- Личная папка у каждого своя. Владелец может открыть файл или папку из неё конкретным людям, и они увидят это в **Shared with me**.
- **Регистрация по ссылке.** В разделе People → **Invite link** IT создаёт ссылку: на сколько дней она действует (до 30), сколько человек могут по ней зарегистрироваться (до 500) и, по желанию, только с какого домена почты (например, `algoritmi.kz`).
  - Ссылка показывается один раз, в базе хранится только её хэш.
  - Человек вводит имя и почту и получает на неё 6-значный код. Код действует 10 минут, даёт 5 попыток ввода, новый код можно запросить не чаще раза в минуту.
  - Затем человек придумывает пароль. Логин берётся из адреса почты, входить можно по логину или по почте.
  - Если на этот адрес уже есть учётка, вместо кода приходит напоминание о логине. Поэтому по странице нельзя проверить, кто зарегистрирован.
  - Новая учётка — обычный сотрудник: видит только свою папку, пока менеджер не откроет доступ. Каждая регистрация попадает в журнал как `ALERT`.
  - Для отправки кодов в `.env` на сервере задаются `SMTP_HOST`, `SMTP_PORT` (465 — TLS, 587 — STARTTLS), `SMTP_USER`, `SMTP_PASS` и `MAIL_FROM`. Без них регистрация выключена.
- **Редактор документов в браузере** (Collabora Online). Word, Excel, PowerPoint и форматы OpenDocument (docx, doc, odt, rtf, xlsx, xls, ods, csv, pptx, ppt, odp) открываются щелчком по имени файла или через меню **Edit in browser**. С правом Read документ открывается только для просмотра, с Edit его можно править. Если несколько человек открыли один файл, они правят его одновременно.
  - Редактор сам сохраняет изменения каждые несколько минут. Одна сессия правки одного человека даёт одну версию (новая начинается через 30 минут), так что файл до правки всегда остаётся в **Versions**.
  - Если файл успели заменить загрузкой, пока его правили, редактор сначала спросит, что делать.
  - **Просмотрщик PDF — EmbedPDF 2.15.1** (MIT, внутри движок PDFium из Chrome, скомпилированный в WebAssembly). Открывается щелчком по любому PDF: чёткий масштаб, миниатюры, поиск, печать. С правом Edit доступны маркер, подчёркивание, заметки, рисование, фигуры, печати, подписи (нарисовать, напечатать или загрузить), заполнение форм и настоящее удаление конфиденциального (redaction). Кнопка **Save** записывает готовый PDF прямо в тот же файл. С правом Read открывается только просмотр.
    - **PDF сохраняется без версий** (решение компании от 19.11.2026): во всех трёх режимах (просмотрщик, Edit text, Edit as Word) старое содержимое заменяется и удаляется с диска. Прежние дни остаются только в ночных бэкапах, 120 дней. Защита от затирания остаётся: если файл успели сохранить после того, как его открыли, запись отклоняется. Word, Excel и другие документы в Collabora по-прежнему дают одну версию на сессию правки, а замена файла загрузкой — новую версию.
    - Файлы лежат в `public/vendor/embedpdf-2.15.1` и раздаются с нашего сервера (кэш на год). CDN, Google Fonts и каталог печатей с jsDelivr выключены в `public/viewer.js`.
    - Просмотрщик живёт на отдельной странице `viewer.html` в рамке. Только этой странице заголовок CSP разрешает WebAssembly, blob-воркер и встроенные стили, остальной сайт остаётся со строгим CSP. Сохранение идёт через `PUT /api/nodes/:id/content`: только PDF, нужно право Edit и проверка версии.
    - Ветка 3.x вышла в ноябре 2026 и обновляется каждые несколько дней, поэтому взята стабильная 2.15.1 от сентября. Русского языка в интерфейсе EmbedPDF нет, он английский, как и весь сайт.
    - Скорость. При сборке образа `scripts/precompress.mjs` готовит сжатые копии (Brotli и gzip) скриптов, стилей и движка: 6,5 МБ превращаются в 1,9 МБ. Файлы сайта отдаются с ETag, и неизменённые не скачиваются заново. Когда в папке есть PDF, браузер заранее подгружает просмотрщик (`prefetchViewer`). Сам PDF скачивается с полосой прогресса и открывается из памяти. Страницы рисуются по мере прокрутки, поэтому длинные документы открываются сразу после загрузки. Загружать файл частями EmbedPDF 2.x не умеет. Потолок скорости — исходящий канал интернета у NAS, примерно 0,15–1 МБ/с извне.
    - На телефоне верхняя панель показывает только значки, у самого EmbedPDF раскладка адаптивная.
  - **PDF-редактор строк** (меню PDF → **Edit text** или кнопка в просмотрщике, нужно право Edit). Страницы показываются в точности как в файле: сервер отдаёт их картинками, а поверх лежат строки текста.
    - **Edit text** — щёлкнуть по строке и исправить. **Add text** — щёлкнуть в любом месте страницы и написать, например заполнить бланк. **Erase** — убрать строку.
    - При сохранении в файле переписываются только изменённые строки. Под строкой удаляется лишь текст, а фон, рисунки и картинки остаются. Новый текст пишется на той же базовой линии шрифтом Liberation той же гарнитуры: Liberation совпадает по ширине с Arial, Times New Roman и Courier New. В файл встраиваются только использованные буквы. Всё остальное в PDF не меняется.
    - Каждое сохранение записывается в тот же PDF, без версии. Если кто-то сохранил PDF раньше, сервер не даст затереть его изменения.
    - Работу делает контейнер `pdfconv` (PyMuPDF): без файлов, без привилегий, файловая система только для чтения. Каждая операция идёт в отдельном процессе с ограничением по времени, поэтому один «тяжёлый» PDF не блокирует остальных.
    - Повёрнутые страницы и сканы (PDF из картинок) показываются, но строк для правки в них нет. На скан можно только добавить текст.
  - Для больших правок — меню PDF → **Edit as Word document**: PDF превращается в документ Word и правится в Collabora, каждое сохранение снова превращается в PDF. Всё считается на NAS, наружу ничего не уходит.
    - Конвертеров два: импорт PDF из LibreOffice (каждая строка, рамка и картинка остаётся на своём месте, картинки в исходном качестве) и pdf2docx (сплошной текст). Оба результата превращаются обратно в PDF и сравниваются с оригиналом по картинке первых страниц, остаётся тот, что ближе. Сравнение слегка размывает картинку, поэтому сдвиг буквы на пиксель почти не считается, а съехавшие таблицы и пропавший текст считаются.
    - После LibreOffice файл Word чинится: позиции отсчитываются от края страницы, а не от полей, а рамки с текстом растут вместе с текстом, чтобы конец строки не обрезался.
    - Результат запоминается для этой версии PDF. Если один из конвертеров падает или зависает, берётся другой.
  - Редактор работает на NAS на отдельном адресе `office.<tailnet>.ts.net` (своя машина Tailscale, Funnel), документы никуда не уходят. Файлов он у себя не хранит: каждый раз получает их у Files по протоколу WOPI с токеном на один файл. Files при каждом обращении проверяет человека, его сессию и права, поэтому блокировка, выход из системы или снятый доступ сразу останавливают правку.
  - Между собой редактор и Files общаются внутри NAS, по сети Docker: `WOPI_URL=http://company-files-tailscale:8801` и `OFFICE_INTERNAL_URL`. Это занимает миллисекунды, а путь через интернет и Funnel занимал секунды. Порт 8801 отвечает только на `/api/wopi/` и слушает адрес контейнера, а не 127.0.0.1, поэтому из tailnet до него не достучаться. Браузер ходит только на `OFFICE_URL`.
  - Служебные API Collabora для конвертации, проверка WOPI-хостов и консоль администратора закрыты в `tailscale/office/serve.json`.
  - Ядро DSM (4.4) не поддерживает собственный фильтр системных вызовов Collabora (seccomp) и пространства имён, поэтому они выключены. Процессы документов всё равно работают в chroot без привилегий и под стандартным seccomp-профилем Docker, в контейнере без файлов и с лимитом памяти 1,5 ГБ. На VPS с новым ядром эта защита работала бы полностью, но там сейчас мало памяти (2 ГБ на шесть проектов).
  - Включается переменной `OFFICE_URL=https://office.<tailnet>.ts.net` в `.env`, без неё редактор скрыт.
- **Загрузка с докачкой** (протокол tus 1.0, клиент tus-js-client 4.3.1). Байты дописываются на сервере по мере прихода. Если пропала связь, закрылась крышка ноутбука или перезагрузилась страница, загрузка продолжается с последнего сохранённого байта.
  - Одновременно идут 6 файлов, мелкие (до 1 МБ) по 12. Число меняется в панели загрузок, выбор хранится в браузере. Файл до 4 МБ уходит одним запросом вместе с созданием. Файлы от 64 МБ идут четырьмя частями параллельно и склеиваются на сервере.
  - Панель загрузок: общий прогресс, скорость за последние 5 секунд, оставшееся время, прогресс каждого файла, **Pause** / **Resume**, **Cancel** (сервер сразу удаляет принятое), **Retry failed**. Без сети файл помечается «No connection» и продолжается сам, когда связь вернулась.
  - После перезагрузки панель показывает незавершённые загрузки. Чтобы продолжить, нужно выбрать те же файлы или ту же папку в то же место. Незавершённое удаляется через 3 дня.
  - **Папки целиком**: кнопкой **Upload folder** или перетаскиванием, со всеми подпапками. При перетаскивании переносятся и пустые подпапки (кнопка выбора папки их не передаёт, так устроены браузеры). Сначала одним-двумя запросами создаётся вся структура (`POST /api/nodes/:id/tree`), потом в неё грузятся файлы. На телефоне кнопки нет, потому что телефоны не умеют выбирать папку.
  - **Download as ZIP** (кнопка в папке и пункт меню у папки) собирает zip на лету, без временного архива. Файлы кладутся без сжатия, поэтому процессор NAS не нагружается, а длина известна заранее и браузер показывает оставшееся время. Внутри пустые папки и только то, что человек может открыть. Архивы больше 4 ГБ пишутся в формате ZIP64. Скачивание учитывается в часовом лимите (500 файлов или 20 ГБ), и превышение видно до начала скачивания.
  - Максимальный размер файла 50 ГБ (`MAX_FILE_GB`). На компьютеры папки уходят через агент автосохранения со структурой.
- **Автосохранение на компьютер** (агент в трее, `agent/`, Go). Человек выделяет файлы или папки и нажимает Enter. Они сохраняются на все его подключённые компьютеры со структурой папок, по умолчанию в `Документы/Company Files`. Выключенный компьютер получает их, когда снова включится.
  - Подключение. На странице «Account and security» есть кнопка **Download**, которая сама определяет систему, и кнопка **Connect this computer**. Сайт выдаёт одноразовый код на 10 минут и открывает `myfiles://pair?code=…`. Агент показывает, к чьей учётке подключается, и подключается только после «Да». Если ссылка не открылась, код можно ввести в меню агента. Компьютер получает свой токен; на сайте видно его статус (online/offline), сколько файлов ждёт сохранения, и кнопку **Disconnect**.
  - Агент держит WebSocket (по нему приходит только «очередь изменилась»), файлы скачивает по HTTPS. При каждом подключении проверяет всю очередь.
  - Пути вида `../`, абсолютные пути, диски, `\`, имена устройств Windows (`con`, `nul`) отклоняются или обезвреживаются. Проверяется и выход через символические ссылки. Ничего не перезаписывается: при совпадении имени получается `файл (1).txt`. Временный файл не пишется через подложенную ссылку.
  - Меню в трее: открыть папку, сменить папку, ввести код, открыть сайт, автозапуск, скрытый режим (без значка; значок возвращается повторным запуском из меню «Пуск»), отключить компьютер, выход.
  - **Windows**: `CompanyFiles-Setup.exe` при первом запуске ставится в профиль пользователя (`%LOCALAPPDATA%\Programs\CompanyFiles`), права администратора не нужны. Он добавляет ярлык в «Пуск», автозапуск и ссылку `myfiles://` и появляется в «Параметры → Приложения», откуда удаляется без следов. **Linux**: `.deb` (`/usr/bin/company-files-agent`, ссылка `myfiles://` через .desktop). **Mac**: `.dmg`, одно приложение для Intel и Apple Silicon. Его нужно перетащить в «Программы».
  - Сборка. `agent/build.ps1` (Windows) или `agent/build.sh` (Linux) собирает `.exe` и `.deb` в `downloads/`. `.dmg` собирает `.github/workflows/agent.yml` на macOS (`agent/build-mac.sh`), там же есть сборка `.exe`/`.deb`. Иконка, манифест (запуск без прав администратора, чёткость на HiDPI) и `.deb` делаются своим кодом (`agent/tools/pack`), без сторонних утилит. Готовые файлы кладутся в `downloads/` и выкатываются вместе с сайтом.
  - Подпись ставится, только если есть сертификат: для Windows `SIGN_PFX` + `SIGN_PASSWORD` (локально нужен signtool, в GitHub — секреты `WINDOWS_PFX`, `WINDOWS_PFX_PASSWORD`); для Mac секреты `MACOS_CERT_P12`, `MACOS_CERT_PASSWORD`, а для нотаризации ещё `APPLE_ID`, `APPLE_TEAM_ID`, `APPLE_APP_PASSWORD`. Без сертификата файлы не подписаны: Windows показывает «Неизвестный издатель» (Подробнее → Выполнить в любом случае), Mac спрашивает один раз (правый клик → Открыть).
- **Корзина:** 30 дней. Кнопка **Delete forever** стирает сразу, и файлы, и их версии. Это может тот, кто может восстановить элемент. В ночных бэкапах копия хранится 120 дней.
- Папка наследует доступ сверху.
- **Restricted**-папка наследует только Manage (начальника) и группу Managers, остальных добавляют поимённо. Это строка «Restricted subfolder» из таблицы ТЗ.
- **Confidential** — только поимённо (группы запрещены, кроме Managers, если так решит руководство), внешние ссылки выключены. При создании папки IT назначает **владельца**, он получает Manage. Владелец сам делится папкой через **Who has access → Edit**: добавляет конкретных людей с Read или Edit и убирает их, без IT. Добавить группу или выдать Manage он не может. Каждое изменение попадает в журнал как `ALERT`.
- В боковой панели папки показаны деревом. Путь к открытой папке раскрыт, её подпапки видны под ней, любую папку можно раскрыть стрелкой.
- Пользователь видит только папки, к которым у него есть доступ.
- **Учётка admin не имеет доступа к файлам вообще**: её нельзя добавить в группу или в список доступа. IT управляет людьми и структурой, а не содержимым. Все изменения прав пишутся в журнал. Managers видят журнал целиком, admin — без файловых событий.

## Безопасность

- Пароли хранятся в виде scrypt-хешей. Вход защищён от перебора: 5 ошибок на логин или 30 на IP, затем блокировка на 15 минут.
- Вход только по логину (или почте) и паролю. 2FA убрана по решению компании 18.11.2026, поэтому пароли должны быть длинными (от 12 символов, сервер это проверяет). Временный пароль от IT нужно сменить до открытия любых папок.
- Сессии хранятся на сервере, cookie HttpOnly + SameSite=Strict, при HTTPS ещё `__Host-` и Secure. Заблокированный сотрудник выкидывается со всех устройств сразу.
- Защита от CSRF (кастомный заголовок + проверка Origin), строгий CSP, nosniff, HSTS при HTTPS.
- Файлы лежат на диске под случайными ID, а не под своими именами, поэтому выйти за пределы хранилища через путь нельзя. HTML, SVG и прочее отдаётся только как скачивание в sandbox; предпросмотр есть только для картинок и PDF.
- Внешние ссылки: создать может только руководитель проекта, только внутри проекта, со сроком до 30 дней. Пароль (16 случайных символов) придумывает сервер и показывает один раз, поэтому слабым он быть не может. Подбор пароля ограничен по IP, а общей блокировки ссылки нет, чтобы держатель ссылки не мог запереть настоящего получателя.
- Журнал аудита только дописывается: UPDATE и DELETE запрещены триггером в БД.
- Тормоз на массовое скачивание. Больше 500 разных файлов или 20 ГБ за час с одного человека или одной внешней ссылки — и загрузки встают на паузу, а в журнале появляется `ALERT download limit reached` (видят Managers). Файл считается и попадает в журнал один раз в час, как бы его ни получали: целиком, кусками по Range или как предпросмотр. Пороги задаются `DOWNLOAD_LIMIT_FILES` и `DOWNLOAD_LIMIT_GB`.
- **Перенос.** Перенести файлы из общих разделов в личную папку нельзя. У владельца личной папки там Manage, и иначе любой с правом Edit мог бы перенести папку отдела к себе, переписать ей доступ и вернуть обратно. Папку со своими настройками доступа в другой раздел переносит только тот, кто может управлять доступом в месте назначения. Защита закрытых подпапок учитывает и те, что лежат в корзине.
- **Загрузки.** Незавершённые загрузки (tus) видны и продолжаются только их автором. На одного человека не больше 20 000 незавершённых загрузок и вдвое больше максимального размера файла, и место на диске проверяется с учётом всего недогруженного. Обычные загрузки: у одного человека одновременно не больше двух файлов максимального размера. Загрузка, которая шлёт меньше 16 КБ в минуту, обрывается. Права на папку и на заменяемый файл перепроверяются в момент записи.
- В корзине и во внешних ссылках не видно закрытых папок, к которым у человека нет доступа. Токены ссылок видит только руководитель проекта.
- **Подбор.** IPv6-адреса ограничиваются по сети /64. Вход по почте и по логину делит один лимит попыток.
- Запросы с чужим `Host` получают отказ 421: это защита от DNS rebinding и от прямого обращения к порту в обход HTTPS. Загрузка останавливается, если на диске остаётся меньше `MIN_FREE_GB` (по умолчанию 20 ГБ). Параллельные загрузки не могут обойти квоту.
- В журнале каждый видит только строки о папках, которые сам может открыть. Менеджер не узнает из журнала имена файлов в Payroll, если у него нет туда доступа. IT видит только системные папки, дальше путь обрезается до `… / …`.
- Чувствительные действия IT помечаются `ALERT`, и Managers видят их через фильтр «Alerts only»: доступ к конфиденциальным папкам, добавление в Managers, сброс пароля у человека с доступом к защищённым папкам, создание админа. Так IT не может тихо завести подставную учётку.
- Папку с групповым доступом нельзя перенести в конфиденциальную или личную. Чтобы удалить или переместить папку, нужен Edit на все закрытые папки внутри неё.
- Квота считает и старые версии, и корзину. Блокировка после неудачных входов действует на пару «логин + компьютер», поэтому чужой не может заблокировать вас со своего компьютера.
- Внешние ссылки перестают работать, как только их создатель заблокирован или больше не управляет папкой.
- В контейнере приложение слушает `127.0.0.2`, а не `127.0.0.1`. До него доходит только `tailscale serve` по HTTPS, а прямые подключения из tailnet к порту 8800 отбрасываются.
- Приложение никуда не ходит в интернет: нет CDN, аналитики и телеметрии, шрифты локальные, CSP `default-src 'self'`. Tailscale запущен с `--no-logs-no-support`, поэтому даже его служебные логи не уходят на серверы Tailscale.

## Бэкап (раздел 8 ТЗ)

Если задан `BACKUP_DIR`, сервер сам каждую ночь в `BACKUP_TIME` (по умолчанию 00:00 по времени сервера) делает бэкап и сразу проверяет его. Работа идёт в отдельном процессе и не тормозит сайт. Итог («nightly backup done and verified» или «nightly backup FAILED») пишется в Activity log, админ видит его каждое утро. Внешний cron не нужен.

**Бэкапы зашифрованы** (AES-256-GCM, каждый файл отдельно). Ключ `backup.key` лежит в папке данных и рядом с бэкапами не хранится, поэтому украденная копия бэкапов бесполезна. **Сохраните ключ вне сервера** (менеджер паролей, сейф): без него бэкап не восстановить.

```powershell
npm run backup -- key          # показать ключ, чтобы сохранить его офлайн
npm run backup                 # снимок БД + новые файлы; старше 120 дней удаляются
npm run backup -- verify       # расшифровать последний снимок и проверить целостность
npm run backup -- restore <путь к db-*.sqlite.enc> <пустая папка>   # ключ из папки данных или BACKUP_KEY=<base64>
```

Раз в 3 месяца: `verify` + `restore` во временную папку + запуск с `DATA_DIR` на неё и другим `PORT`.

Корзина хранит удалённое 30 дней, версий хранится 20 на файл. Восстанавливать их пользователи могут сами.

## Развёртывание: Synology NAS + Tailscale

Сейчас приложение работает так. Приложение, база, файлы и бэкапы лежат на NAS. Контейнер Tailscale входит в tailnet отдельной машиной `files` и отдаёт `https://files.<tailnet>.ts.net` с настоящим сертификатом. Funnel включён, так же, как у других сайтов на этом NAS: сайт открывается и из интернета, Tailscale на устройстве не нужен.

- Порты на NAS не открыты. Наружу смотрит только HTTPS на 443 через Funnel (ТЗ 6.3, 7.1–7.2), заработали и внешние ссылки для подрядчиков.
- Вход и из интернета, и из tailnet одинаковый: логин и пароль.
- Одновременно идёт не больше 2 проверок пароля. У контейнера пониженный приоритет на процессор (`cpu_shares: 512`), чтобы ботнет не загрузил NAS. Стоят `robots.txt` и `X-Robots-Tag: noindex`.
- Чтобы снова сделать сайт только для tailnet, уберите `AllowFunnel` из `tailscale/serve.json`.

| Что | Где на NAS |
|---|---|
| код, `docker-compose.yml`, `.env` (запись только root) | `/volume1/docker/company-files` |
| база, файлы, ключи | Docker-том `company-files_data` (не общая папка: не видна в File Station, SMB и DSM) |
| ключ машины Tailscale | Docker-том `company-files_ts-state` |
| зашифрованные бэкапы, 00:00, 120 дней | `/volume1/Backups/CompanyFiles` |

`.env` на NAS (переменные для compose): `BACKUP_ROOT`, `PUBLIC_URL=https://files.<tailnet>.ts.net`, `TS_HOSTNAME=files`, при желании `TS_AUTHKEY`.

**Никогда не запускайте `docker-compose down -v`**: флаг `-v` удаляет тома, то есть все данные.

Ключ бэкапов, чтобы сохранить офлайн: `docker exec company-files node scripts/backup.mjs key`.

Любой администратор DSM по сути root на NAS. Поэтому у учёток администраторов DSM должны быть сильные пароли и 2FA.

Обновление после правок кода (по SSH, под root):

```sh
export PATH=/usr/local/bin:$PATH        # иначе docker-compose не найдёт docker
cd /volume1/docker/company-files && docker-compose build app && docker-compose up -d
docker exec company-files node scripts/admin.mjs   # сброс пароля учётки admin
```

**После перезагрузки NAS сайт может отвечать 502.** Приложение живёт в сети контейнера Tailscale. Если Docker при загрузке запустит его раньше этого контейнера, старт не удастся, а повторять его Docker не станет. Так было 17.11.2026. Поднять вручную (по SSH, под root):

```sh
export PATH=/usr/local/bin:$PATH && cd /volume1/docker/company-files && docker-compose up -d
```

Теперь это происходит само. С 18.11.2026 на NAS работает общий сторож `nas-watchdog.sh`, один на все контейнеры, нынешние и будущие, настраивать ничего не нужно. Лежит в `/volume1/docker/nas-watchdog/`, запускается задачей DSM «Docker watchdog» (Boot-up, root). Раз в минуту он чинит два случая:

- Контейнер с политикой `always`/`unless-stopped` не смог запуститься (например, при загрузке раньше контейнера, в чьей сети он живёт). Docker такой запуск не повторяет, а сторож делает `docker start`.
- Контейнер работает в сети другого контейнера, а тот перезапустился. Сторож делает `docker restart`.

Больше он ничего не трогает: выключенные и остановленные вручную контейнеры не запускает. Его журнал — `watchdog.log` рядом со скриптом. Пробный прогон, который ничего не меняет: `ONCE=1 DRY=1 bash /volume1/docker/nas-watchdog/nas-watchdog.sh`. Исходник лежит в этом репозитории. Обновить: скопировать файл в ту папку и перезапустить процесс (команда в шапке скрипта).

**Копия вне NAS (ТЗ 8.1).** С 18.11.2026 скрипт `nas-offsite.sh` (исходник в этом репозитории, на NAS лежит в `/volume1/docker/offsite-backup/`, запускается задачей DSM «Offsite backup») каждый день в 05:30 отправляет на VPS в Казахстане (`92.38.49.216`, папка `/var/lib/nasbackup/nas`) два набора:

- `daily/nas-ДАТА.tar.gz.gpg` — все проекты NAS, кроме OncePlatform. Внутри свежие дампы всех работающих PostgreSQL, копии всех SQLite-баз, папки проектов (настройки, `.env`, код) и мелкие тома Docker. Новые проекты попадают туда сами. Архив зашифрован (gpg, AES-256) ключом `offsite.key`, который есть только на NAS. На VPS хранятся последние 30 дней.
- `company-files/` — зеркало зашифрованных бэкапов этого приложения.

На VPS NAS заходит пользователем `nasbackup`. Его ключ ограничен `rrsync` этой одной папкой: командной строки нет. Журнал — `offsite.log` рядом со скриптом. Ручной запуск: `ONCE=1 bash nas-offsite.sh`. Если NAS был выключен в 05:30, архив соберётся сразу после включения.

**Ключ `offsite.key` нужно хранить ещё и вне NAS** (в менеджере паролей), иначе архивы на VPS не открыть: `cat /volume1/docker/offsite-backup/offsite.key`. Восстановление: `gpg --batch --passphrase-file offsite.key -d nas-ДАТА.tar.gz.gpg | tar xzf -`.

Учтите:
- `DATA_DIR` при локальном запуске не держите в OneDrive: синхронизация портит базу SQLite.
